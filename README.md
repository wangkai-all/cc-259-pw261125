# 共同分析仓库 · 授权版本 × 执行计划 × 分页交付 × 缓存

一个可真实查数据的本地网页：SQLite 里有 1,600 行事实数据，按**列**和**组织（行）**授予读取范围。授权会以**不可变版本**发布；用户可能在查询执行中、翻页间隙或下载分块之间被撤权。

目标不是账号管理页，而是把四件事关联起来：

1. **授权版本**：每次发布生成新版本，旧版本保留，查询可固定到某个快照。
2. **执行计划**：真实 `EXPLAIN QUERY PLAN`，以及本次查询的“实际可用作用域”。
3. **结果分页**：已交付页冻结，未交付页逐页重新授权。
4. **缓存**：按“实际授权作用域”取键，跨主体共享，撤权不删除、窄授权不复用宽结果。

## 快速开始

```bash
python3 -m app.server --reset        # http://127.0.0.1:8765
```

无第三方依赖，Python 3.11+。数据默认写入 `data/analytics.sqlite3`，可用 `SHAN_DATA` 改目录。

打开页面后以 **admin-root**（管理员）身份先点「运行样例：撤权撞上任务恢复」，再切换到 **Ada / Cy** 观察各自视角。

## 关键决策

### 启动时固定，还是每次交付重新检查？

**两者都实现，由发起查询的人选择，且不互相替代：**

| | `pinned` | `recheck` |
|---|---|---|
| 执行阶段读取 | 启动时冻结的快照 | `启动快照 ∩ live grant`（取窄者） |
| 慢查询中途撤权 | 引擎仍可能算出被撤行 | 被撤列/组织立即不参与执行 |
| 交付（分页/分块） | **仍然逐次检查 live grant** | 逐次检查 live grant |
| 典型用途 | 可复现报表、审计对账 | 在线即席查询 |

无论哪种模式，**交付层永远重新授权**。这是刻意的：执行需要一致性，交付需要时效性。

### 已经交出的数据无法收回

- 每个成功交付的分页写入 `page_deliveries`，包含冻结的行字节。
- 重复请求同一页返回完全相同的字节，标注 `replay: true`。撤权不会、也无法修改它。
- 下载任务记录 `download_delivered`（行身份），已交付分块不会重发，也不会被回溯删除。

### 尚未交付的部分如何处理

- 每个新分页/分块在交付前与 live grant 求交。
- 被撤的**列**从投影中移除；被撤的**组织**从行集中移除。
- 聚合结果不是简单删行：会从**授权范围内的明细**重新聚合（`query_detail`），因此旧 `SUM` 不会把被撤组织的金额带出去。
- 若剩余可交付为空：返回 `nothing_left_to_deliver` 并附扣留的列/组织；完全没有可用范围时返回 `scope_revoked` 并写入拒绝记录。
- 下载任务若因撤权而无法交付剩余分块，会标记 `truncated_by_revocation`，而不是显示一个掩盖问题的“完成”。

### 分页不会因撤权而错位

分页按**行身份**（分组的维度值或 row_key）而非偏移量选择。撤掉一个组织后，未交付窗口不会整体前移导致跳过或重复行。下载分块同理。

### 缓存：共享，但不越权

- 键 = SQL 形状 + 实际授权列 + 实际授权组织 + 数据代际（`data_epoch`）。**不含主体 ID**。
- 同作用域的其他分析员直接命中同一条缓存；发布授权**不会**清空缓存。
- 撤权者的作用域变窄 → 键不同 → 不会命中宽缓存，也不会看到宽结果。
- 缓存条目**永不因某个人的撤权而删除**；同组仍有权限的人继续使用。
- UI 的“缓存”页显示近似条目（`extra_*/missing_*`）解释为什么没命中。

### 游标与拒绝依据

- 游标绑定 `(query, principal)`；他人复用直接 `cursor_principal_mismatch`。
- 每次撤权引发的拒绝写入 `denials`：`kind`、`code`、`reason`、live 版本、扣留的列/组织，可在页面右侧“拒绝依据”复核。

## 代码结构

```
app/db.py         schema、种子数据、连接（autocommit + WAL）
app/authz.py      授权版本、快照、求交、拒绝记录
app/engine.py     编译查询、执行作用域、缓存键/查找、明细落库
app/delivery.py   分页冻结/重授权、缓存重算、下载分块
app/server.py     HTTP API + 单页 UI + 样例场景
app/static/       前端（无框架）
tests/            不变量测试
```

## 已知边界

- 自由 SQL 仅作只读预览，必须投影 `organization` 才能强制行范围；复杂 SQL 的重授权仍以明细重算为主。
- 这是本地模拟：身份来自 `X-Principal` 请求头，没有认证；“管理员”仅用于发布授权和重置。
- 缓存没有 TTL/内存淘汰，数据代际由 `system_state.epoch` 手动推进。
